Code 2/4 · common-library

BankingException: apna exception

exception/BankingException.java done
@Getter
public class BankingException extends RuntimeException {

    private final ErrorCode errorCode;

    public BankingException(ErrorCode errorCode, String message) {
        super(message);
        this.errorCode = errorCode;
    }

    public BankingException(ErrorCode errorCode, String message, Throwable cause) {
        super(message, cause);
        this.errorCode = errorCode;
    }

    public BankingException(String message) {
        this(ErrorCode.INTERNAL_ERROR, message);
    }

    public HttpStatus getStatus() {
        return errorCode.getStatus();
    }
}
RuntimeException kyun? Unchecked exception hai, toh har method par throws ya try-catch likhna zaroori nahi.

Service mein aise use hoga (aage likhna hai):

throw new BankingException(
    ErrorCode.ACCOUNT_NOT_FOUND,
    "Account ACC-1001 nahi mila");

Code 3/4 · common-library

ApiResponse, ErrorResponse, PagedResponse

dto/*.java done (teen files, chhota kiya)
@JsonInclude(JsonInclude.Include.NON_NULL)
public class ApiResponse<T> {
    private final T data;
    private final ErrorResponse error;

    public ApiResponse(T data) { this.data = data; this.error = null; }
    public ApiResponse(ErrorResponse error) { this.data = null; this.error = error; }
}

public class ErrorResponse {
    private final String message;
    private final String code;
    private final int status;

    public ErrorResponse(ErrorCode errorCode, String message) {
        this.code = errorCode.name();
        this.message = message;
        this.status = errorCode.getStatus().value();
    }
}

@Builder
public class PagedResponse<T> {
    List<T> data; int page; int size;
    long totalElements; int totalPages; boolean last;
}

    Java + Spring basics
    
      
    Concepts jo is code mein baar-baar aayenge
    
    
    
    
    
      
    Maven: parent, modules, scope
    Root pom.xml parent hai aur modules ki list rakhta hai. dependencyManagement sirf version tay karta hai. scope batata hai ki library kab chahiye: test sirf tests mein, runtime sirf chalte waqt.
    mvn clean install          # sab build
mvn -pl account-service spring-boot:run
    
      
    enum
    Fixed constants ki list. Har constant ek object hai, jiske apne fields aur constructor ho sakte hain. Aapke ErrorCode aur EventType dono enums hain.
    ErrorCode c = ErrorCode.ACCOUNT_NOT_FOUND;
c.name();       // "ACCOUNT_NOT_FOUND"
c.getStatus();  // HttpStatus.NOT_FOUND
    
      
    Generics <T>
    T ek placeholder type hai. Ek hi class har type ke data ke saath kaam karti hai, aur compiler type check bhi karta hai.
    ApiResponse<AccountResponse> a;
PagedResponse<TransactionResponse> p;
    
      
    final, static, abstract
    final field ek baar set hoti hai. static cheez class ki hoti hai, object ki nahi. abstract class ka seedha object nahi banta, sirf extend hoti hai.
    BaseEvent e = new BaseEvent();  // error: abstract
EventType.Topics.ACCOUNT         // static, no object
    
      
    Lombok
    Boilerplate code compile ke time par khud likh deta hai. Source mein dikhta nahi, lekin .class file mein hota hai.
    @Getter               → getX()
@Setter               → setX(..)
@NoArgsConstructor    → new X()
@RequiredArgsConstructor → final fields ka constructor
@Builder              → X.builder().a(1).build()
    
      
    Jackson (JSON)
    Spring Java objects ko JSON mein (aur wapas) Jackson se badalta hai. Getters se JSON fields bante hain.
    @JsonInclude(NON_NULL) → null field skip
@JsonIgnore            → field/getter skip
    
      
    Checked vs unchecked exception
    Exception (checked) ko pakadna ya throws likhna zaroori hai. RuntimeException (unchecked) mein nahi. Spring @Transactional default rollback sirf unchecked par karta hai.
    class BankingException
    extends RuntimeException  // unchecked
    
      
    Spring ke main annotations
    Spring in annotations wali classes ke objects (beans) khud banata hai aur constructor ke through ek doosre mein daal deta hai. Isko dependency injection kehte hain.
    @RestController  HTTP endpoints
@Service         business logic
@Repository      DB (JpaRepository)
@Transactional   sab ya kuch nahi
